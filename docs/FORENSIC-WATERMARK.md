# 외부 유출 탐지 엔진

## 동작 방식

1. 열람 권한이 확인된 뒤 `issue_reader_watermark`가 서버 난수 토큰을 발급합니다.
2. 토큰은 사용자 ID·작품·회차·발급 시각과 서버의 `reader_watermark_issues` 이력으로 연결됩니다. 토큰 문자열 자체에는 개인정보를 넣지 않습니다.
3. 리더는 토큰을 24×24 미세 픽셀 패턴으로 여러 위치에 반복 표시하고, 동시에 사람이 읽을 수 있는 사용자 식별 워터마크를 표시합니다.
4. 신고자는 게시글·댓글 신고창에서 JPG·PNG·WEBP 사진을 첨부할 수 있습니다. 브라우저 스캐너는 픽셀 패턴 후보와 신뢰도를 계산하고 원본 사진을 비공개 `report-evidence` 버킷에 보존합니다.
5. 후보 토큰은 `match_report_watermark` RPC가 서버 발급 이력과 대조합니다. 일치하면 운영자 신고 큐에 발급 사용자와 발급 시각을 표시합니다.

## 판정 원칙

- 자동 탐지는 제재의 단독 근거가 아닙니다. 사진 압축, 리사이즈, 재촬영, 기울기, 화면 밝기와 일부 잘림에 따라 탐지 신뢰도가 달라집니다.
- `detected`는 서버 발급 이력과 일치한 경우에만 사용합니다. 패턴 후보만 찾았거나 대조에 실패하면 `needs_review`로 운영자 확인을 요구합니다.
- 원본 증거, SHA-256, 업로드 계정, 신고 시각을 함께 보존하고 접근은 신고자와 moderator 관리자만 허용합니다.

## 출시 전 필수 작업

- `supabase/migrations/0005_forensic_watermarks.sql`을 Supabase 프로젝트에 적용합니다.
- `report-evidence` 버킷이 비공개인지 확인하고, Storage 정책과 moderator 역할을 점검합니다.
- PNG/JPEG 원본·재압축·모바일 재촬영 샘플로 탐지율/오탐률을 측정합니다.
- 자동 일치만으로 계정 정지하지 않고 원본 확인, 작가 확인, 이의제기 기록을 남깁니다.
- 증거 보존 기간, 삭제 요청, 저작권 신고·반론 절차를 실제 운영자와 법률 전문가가 확정합니다.
